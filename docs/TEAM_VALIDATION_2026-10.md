# 多 Agent 工作流验证记录（2026-10-15）

本记录验证功能分支的协作接口和工程约束。测试对象包括 7 类原创论证结构、
按功能筛选、独立角色材料、状态恢复、审查门槛和修订历史。
它不声明英文写作收益、总 token 节省或人工审稿人认可。

## 验收条件与验证方式

| 条件 | 验证方式 |
|---|---|
| 结构卡引用可追踪且不重复另建术语库 | 校验既有词条、指南、study JSON Pointer；检查重复结构和 provenance |
| 按章节、意图、证据关系、实验类型命中 | 真实 CLI 查询、已知不匹配、未知标签和完整预算边界 |
| 每个阶段获得必要且有界的材料 | 检查 writer 保留原始事实；planner 不见语言 bundle；两份 review 不见彼此 |
| 不完整、过期或自审不能放行 | 缺失证据/主张/片段/检查项、错误哈希、复用 reviewer actor、提前 export 的拒绝路径 |
| 修订、并发、恢复不损坏状态 | 两线程提交、旧审查失效、最大轮次、重新启动进程导出原文、文件损坏拒绝 |
| 来源与输入不会触发任意执行 | 严格 JSON、未知字段、路径和 symlink、非正规文件、大小限制、无模型/网络客户端 |
| 原有使用方式保持兼容 | 原有 corpus 校验、42 条检索回归、完整单元测试、确定性构建与生成文件无漂移 |
| 宿主真的能完成角色调用 | 两轮开发试运行，各使用 5 个独立原生 Agent 会话；协调者只提交原始 JSON |

配置读取不依赖 POSIX 锁的可用性；仅进入 team 运行时才要求该能力。
已测试 macOS 与模拟缺少锁能力的拒绝路径；没有宣称 Windows 端到端执行通过。
`actor_id` 是宿主记录，输入哈希是完整性检查，两者都不是身份认证或 OS 隔离。

## 第一轮真实协作与发现的问题

任务来自之前已经核验的 RSS 2025 OpenVLA-OFT Table II 公开数字，使用
[同一份输入](../examples/team/experiment-task.json)。给定事实涵盖 L1 与
50/10/1 步 diffusion、生成吞吐量和 LIBERO-Long 成功率。作者原分析段落没有
交给工作 Agent；本轮也没有重新声称做了一级来源核验。

证据读取、规划、写作、事实审查、叙事审查分别使用新会话；并行审查互不读取。
原始 accepted artifact 保存在
[`initial.state.json`](../evals/team-smoke-2026-10/initial.state.json)，包括冻结的
任务、材料、角色契约、主张映射和两位审查者的原判断。正文未由协调者润色。

两位审查者都给出 `pass`。维护者随后发现：首稿仍按方法与步数逐项陈述数值，
结尾花了较多篇幅罗列不支持的统计及因果解释。这是明确的开发观察：事实覆盖与
角色分工已经成立，但当时的叙事审查标准过于宽松，不能据此宣称专业表达得到提升。

因此修订了角色契约：规划者先提出中心发现，让证据对比服务它；范围约束可以
作为已有主张的限定，不强制变成单独一条免责声明；写作者不机械地把每个计划项
转成一个句子；叙事审查要判断数值对比是否发展了中心发现。

旧运行保留原契约，不能用后来更严格的指令改写它的历史。第二次使用新运行和
新角色会话检查修订后的契约。由于调整已经参考首稿，该过程属于开发迭代，
不是独立盲测、样本外结果或单 Agent／多 Agent 的因果对照。

第二次完整运行也通过两位新审查者的检查并导出原文，见
[`refined.state.json`](../evals/team-smoke-2026-10/refined.state.json)。新版计划
由“中心发现 → 中间工作点 → 失败边界与方法对比”组织，正文不再用一长串
统计与因果免责声明收尾。初版 105 词、第二版 104 词（按空白分词），因此这次
调整主要改变组织方式，不能用篇幅差异解释成质量或成本收益。

两版未编辑正文、计划、全部审查意见与冻结契约均被保留。
[`manifest.json`](../evals/team-smoke-2026-10/manifest.json) 记录运行身份、独立角色、
已暴露和未暴露的生成条件，以及完整 packet 的字符数。第二版 writer packet
为 25,307 字符，包含原始事实、计划、结构卡、语言 bundle 和输出约定；各角色
完整 packet 都低于各自上限。该数字排除了宿主系统/Skill 指令及模型输出，
不是总模型 token 或费用统计。两个 live run 都未触发运行内修订；修订、失效
审查和上限分支由明确的状态机回归覆盖。

## 工程问题的修正证据

- 并行 review 的初版锁处理会拒绝正常竞争；独立测试复现后改为串行文件锁，
  两份审查均被保留。
- `contrast + tradeoff + efficiency` 初版返回空结构，`compare` 能命中。
  修正结构卡意图标签后，相同 CLI 回归从失败转为通过。
- 把角色指令和输出约定一起冻结，避免后续纯措辞修改改变既有 packet 的哈希；
  已用运行中替换模块常量的回归验证。
- 补充缺少 POSIX 锁的明确运行时拒绝，避免配置校验影响普通语料检索。

## 可重跑检查

```bash
make check
python3 -m unittest discover -s tests -p 'test_team*.py' -v
python3 -m py_compile scripts/superlib.py scripts/argument_frames.py scripts/team_workflow.py
git diff --check
```

`test_team_live_record.py` 把已保存的公开运行复制到临时目录，重新校验历史和
当前审查并导出原文；不把模型评分变成“质量必须提高”的测试断言。
交互架构图通过严格 TypeScript 检查；没有把类型检查描述成 IDE 交互实测。

本地工程验收：`make check` 通过 175 项测试、42/42 检索回归，构建无生成文件
漂移；第二份运行归档及其 manifest 加入后，运行记录回放测试再次通过。
Python 编译和 `git diff --check` 通过，第二版正文的有限措辞 audit 返回 `[]`。
该 audit 只说明没有命中其规则，不能替代数值、科学主张或叙事审查。
本次只更新仓库内现有 Skill 的入口和能力声明，没有安装全局 Skill 或添加模型依赖。
